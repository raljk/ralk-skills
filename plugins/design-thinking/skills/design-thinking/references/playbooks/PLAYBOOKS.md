## Discovery Playbook

### Overview

A structured approach to move from ambiguity to clarity, reducing project risk by investing early in understanding the problem and opportunities.

**Philosophy**: Put early investment into understanding the problem and potential opportunities FIRST, to reduce project uncertainty and risk later — when it is too late to pivot.

### The Three Phases

```
                    Risk ↑
                         │
         1. Identify     │    2. Evaluate      │    3. Deliver
         the right       │    the best way     │    meaningful
         problems        │    forward          │    outcomes
                         │                     │
    ─────────────────────┼─────────────────────┼─────────────────────►
                         │                     │                    Time
    Ambiguity            │                     │              Clarity
                         ▼
                    $ Investment
```

---

### Phase 1: Identify the Right Problems

**Purpose**: Focus on validating ideas early — find out just enough information about as many opportunities as possible to make an informed decision.

**Duration**: 1-2 weeks

**Activities**:
- Ideation sessions
- Desktop research
- Competitor analysis
- Customer and stakeholder interviews

**Outputs**:
- Current state experience maps
- Competitor analysis report
- Pain points and opportunity areas summary
- Research synthesis

---

### Phase 2: Evaluate the Best Way Forward

**Purpose**: Focus energy, time and resources on opportunities that are viable for the business, and cut the ones that are not.

**Duration**: 1-2 weeks

**Activities**:
- Concept validation
- Tech feasibility assessment
- Business prioritisation
- Opportunity sizing

**Outputs**:
- Validated concepts
- DVF (Desirability, Viability, Feasibility) assessment
- Prioritised opportunity list
- High-level roadmap

---

### Phase 3: Deliver Meaningful Outcomes

**Purpose**: Rapid, iterative build of a Minimum Viable Product that meets the needs of early-adopters; and that can be tested and measured continuously.

**Duration**: 2-4 weeks

**Activities**:
- Prototyping
- User research and testing
- Roadmap development
- Delivery planning

**Outputs**:
- Validated prototype
- Usability testing insights report
- Implementation roadmap
- Delivery-ready designs

---

## Design Sprint Playbook

### Overview

A multi-day process to design, prototype and test ideas with users. Derived from Google Ventures methodology, adapted for various contexts.

**Duration**: 4-5 days (can be compressed to 2-3 days)

### Day-by-Day Structure

#### Day 1: Map & Understand

**Morning**:
1. Set a long-term goal (15 mins)
2. List sprint questions (15 mins)
3. Make a map of the challenge (45 mins)

**Afternoon**:
4. Ask the experts (Lightning talks) (60 mins)
5. Target selection — pick a focus (15 mins)

**Key Output**: Challenge map with target area identified

---

#### Day 2: Sketch Solutions

**Morning**:
1. Lightning demos — review inspiring solutions (45 mins)
2. Divide or swarm (15 mins)

**Afternoon**:
3. Four-step sketch:
   - Notes (20 mins)
   - Ideas (20 mins)
   - Crazy 8s (8 mins)
   - Solution sketch (30 mins)

**Key Output**: Individual solution sketches

---

#### Day 3: Decide

**Morning**:
1. Sticky decision process:
   - Art museum (silent review) (10 mins)
   - Heat map (dot voting) (10 mins)
   - Speed critique (3 mins per sketch)
   - Straw poll (5 mins)
   - Supervote (decision maker chooses) (5 mins)

**Afternoon**:
2. Rumble or all-in-one (decision on approach)
3. Storyboard the prototype (2-3 hours)

**Key Output**: Storyboard ready for prototyping

---

#### Day 4: Prototype

**Full Day**:
1. Assign roles:
   - Makers (2+)
   - Stitcher (1)
   - Writer (1)
   - Asset collector (1)
   - Interviewer (1)
2. Build the prototype
3. Trial run

**Key Output**: Realistic prototype ready for testing

---

#### Day 5: Test

**Morning/Afternoon**:
1. Run 5 user interviews (60 mins each)
2. Team watches and takes notes
3. Real-time synthesis between interviews

**End of Day**:
4. Look for patterns
5. Review sprint questions
6. Decide next steps

**Key Output**: Validated learnings and clear next steps

---

### Sprint Facilitation Tips

**Before the sprint**:
- Set expectations: sprints produce concepts, not finished products
- Book user interviews well in advance
- Ensure decision maker is present
- Prepare the room with materials

**During the sprint**:
- Enforce timeboxes strictly
- "Together alone" — individual work, group decisions
- No devices during working sessions
- Capture decisions visually

**After the sprint**:
- Results ≠ answers, they're inputs
- Plan the next experiment
- Share findings widely

## Strategy Workshop Playbook

### Strategy by Design

A workshop-based approach to create business strategy aligned to customer value and market opportunity.

**Duration**: 3-5 days

**When to use**:
- Products/services not delivering expected value
- Uncertainty about which initiatives to prioritise
- High-level strategy not linked to practical roadmap
- Need commercial certainty for large investments

### Workshop Flow

#### Pre-Workshop

**Client Questionnaire** covering:
- Business objectives
- Competitive landscape
- Known constraints
- Success criteria

**Stakeholder Interviews**:
- Executive sponsors
- Product owners
- Technical SMEs

---

#### Day 1: Current State

**Activities**:
1. Context Canvas (60 mins)
   - Demographic trends
   - Competitors
   - Technology trends
   - Uncertainties

2. Business Model Canvas (90 mins)
   - Value proposition
   - Infrastructure
   - Customers
   - Finances

**Output**: Shared understanding of current reality

---

#### Day 2: Customer & Market

**Activities**:
1. Journey Mapping (90 mins)
   - Map end-to-end customer experience
   - Identify highs and lows
   - Uncover touchpoints and insights

2. Value Proposition Design (60 mins)
   - Customer jobs, pains, gains
   - Product/service fit

**Output**: Customer-validated value proposition

---

#### Day 3: Future State

**Activities**:
1. Blue Ocean Strategy Canvas (90 mins)
   - Analyse existing value proposition
   - Identify differentiation opportunities
   - Map against competitors

2. Risks and Assumptions (60 mins)
   - List all assumptions
   - Assess impact if wrong
   - Design tests to validate

**Output**: Differentiated strategy with risk register

---

#### Day 4: Prioritisation

**Activities**:
1. Lean Prioritisation (90 mins)
   - Identify next steps
   - Score by value and effort
   - Sequence by risk

2. Success Metrics (60 mins)
   - Define measurable outcomes
   - Create decision criteria

**Output**: Prioritised initiative list with metrics

---

#### Day 5: Roadmap

**Activities**:
1. Value-Based Roadmapping (120 mins)
   - Prioritise risk across timeframe
   - Articulate standalone goals
   - Align goals with practical outcomes

2. Next Steps & Handover (60 mins)
   - Immediate actions
   - Ownership assignment
   - Governance rhythm

**Output**: Business value roadmap (not feature-based)

---

### Strategy Workshop Outcomes

| Outcome | Description |
|---------|-------------|
| Problem-Solution Fit | Clear validated problem worth solving |
| Product-Market Fit | Validated customer segments and value |
| Prioritised Roadmap | Risk-sequenced path to value |
| Success Metrics | Measurable outcomes and decision criteria |
| Stakeholder Alignment | Shared understanding across functions |

```
│   of            listening to                                            │

│    want to be    opportunities   anyone   are we        usable  still   │

│                                  solution?"             built?"         │
│                                                                         │

│   Sensemaking → Ideas → Experiments → MVPs → Products → Rebirth/Death  │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

### Stage Gates

| Stage | Key Question | Activities | Go/No-Go Criteria |
|-------|-------------|------------|-------------------|
| Sensemaking | Who do we want to be? | Trend analysis, competitor research | Strategic alignment |
| Ideas | What opportunities exist? | Brainstorming, HMW questions | Feasibility check |
| Experiments | Does anyone want this? | Prototypes, user testing | Desirability validated |
| MVPs | Can we build and scale? | Minimum viable build | Viability confirmed |
| Products | Are we delivering value? | Full launch, iteration | Market traction |

### Innovation System Matrix

Use this to plan governance across the pipeline:

| Dimension | Sensemaking | Ideas | Experiments | MVPs | Products |
|-----------|-------------|-------|-------------|------|----------|
| **Decisions** | Strategic direction | Which to pursue | Continue/pivot | Scale/kill | Iterate/retire |
| **Stakeholders** | Executive | Innovation team | Cross-functional | Product team | Business unit |
| **Capabilities** | Research, strategy | Design thinking | Prototyping | Engineering | Operations |
| **Culture** | Curious | Creative | Experimental | Resilient | Continuous |
| **Metrics** | Insights generated | Ideas captured | Learning velocity | Time to market | Customer value |

## Kickoff & Alignment Activities

### Project Kickoff Workshop

**Purpose**: Align stakeholders around goals, outputs, timelines and constraints.

**Duration**: 2-4 hours

**Participants**: Key stakeholders, project team, decision makers

**Facilitation Script**:

1. **Welcome & Context** (15 mins)
   - Introduce the project
   - Explain workshop objectives
   - Set ground rules

2. **Background Alignment** (30 mins)
   - Why are we here?
   - What's the broader context?
   - What's been tried before?

3. **Goals & Success Criteria** (45 mins)
   - What does success look like?
   - How will we measure it?
   - What are the constraints?

4. **Roles & Responsibilities** (30 mins)
   - Who does what?
   - Decision-making process
   - Escalation paths

5. **Timeline & Milestones** (30 mins)
   - Key dates
   - Dependencies
   - Risks

6. **Close & Next Steps** (15 mins)
   - Summarise agreements
   - Immediate actions
   - Communication rhythm

**Outputs**:
- Agreed problem statement
- Success criteria
- RACI matrix
- Timeline with milestones
- Risk register

**Facilitator Tips**:
- Nominate a facilitator before the workshop
- Ensure key decision makers are present
- Document agreements visually in real-time
- Address misalignments immediately

---

### Stakeholder Interviews

**Purpose**: Establish project background, constraints, goals and build rapport with decision-makers.

**Duration**: 45-60 mins per interview

**Preparation**:
- Research the stakeholder's role and context
- Prepare tailored questions
- Review any prior documentation

**Interview Guide**:

1. **Opening** (5 mins)
   - Thank them for their time
   - Explain purpose and how input will be used
   - Confirm confidentiality if needed

2. **Context Questions** (15 mins)
   - "What's your role in relation to this project?"
   - "What's the history that led us here?"
   - "What have you tried before?"

3. **Goals & Expectations** (15 mins)
   - "What does success look like for you?"
   - "What would make this project fail?"
   - "What concerns do you have?"

4. **Constraints & Dependencies** (10 mins)
   - "What can't change?"
   - "Who else should we talk to?"
   - "What resources are available?"

5. **Close** (5 mins)
   - "Anything I haven't asked that's important?"
   - Explain next steps
   - Thank them

**Strengths**:
- Builds rapport and trust
- Hears priorities in stakeholder's own words
- Identifies misalignments early

**Challenges**:
- Access to senior stakeholders can be difficult
- Competing priorities may derail conversations
- Be clear on boundaries before starting

## Research & Empathy Activities

### Empathy Mapping

**Purpose**: Put aside our own perspective to understand users' experiences deeply and meaningfully.

**Duration**: 30-60 mins

**Materials**: Large poster paper, sticky notes, markers

**Canvas Structure**:

```
┌─────────────────────────────────────────────────────────────────┐
│                     WHO are we empathising with?                │
│                     What situation are they in?                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────────────────┬─────────────────────────────────┐  │
│  │       THINK & FEEL      │            SEE                  │  │
│  │                         │                                 │  │
│  │  What really matters?   │  What is their environment?    │  │
│  │  Major preoccupations?  │  What do they see others do?   │  │
│  │  Worries and            │  What are they exposed to?     │  │
│  │  aspirations?           │                                 │  │
│  ├─────────────────────────┼─────────────────────────────────┤  │
│  │          HEAR           │            SAY & DO             │  │
│  │                         │                                 │  │
│  │  What do friends say?   │  Attitude in public?           │  │
│  │  What does boss say?    │  Appearance?                   │  │
│  │  What do influencers    │  Behavior toward others?       │  │
│  │  say?                   │                                 │  │
│  └─────────────────────────┴─────────────────────────────────┘  │
│                                                                 │
│  ┌─────────────────────────┬─────────────────────────────────┐  │
│  │         PAINS           │            GAINS                │  │
│  │                         │                                 │  │
│  │  Fears                  │  Wants/needs                   │  │
│  │  Frustrations           │  Measures of success           │  │
│  │  Obstacles              │  Hopes and dreams              │  │
│  └─────────────────────────┴─────────────────────────────────┘  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

**Facilitation Steps**:

1. **Identify Customer** (5 mins)
   - Each person writes a key customer on a sticky note
   - Share briefly with group
   - Select one to explore together

2. **Silent Brainstorm** (10 mins)
   - Everyone writes stickies for each section
   - One thought per sticky
   - Place on canvas

3. **Share & Cluster** (15 mins)
   - Discuss each section
   - Group similar items
   - Identify patterns

4. **Vote** (5 mins)
   - Each person gets 6 votes (one per section)
   - Vote on most salient items

5. **Synthesis** (10 mins)
   - What did we learn?
   - What surprised us?
   - What do we need to validate?

**Empathy Practice Principles**:
1. Abandon your ego — it's not about you
2. Adopt humility — you don't know as much as you think
3. Practice active listening — stop waiting to talk
4. Observe carefully — 93% of communication is non-verbal
5. Care genuinely — be driven by making things better
6. Be curious — surface explanations never uncover truth
7. Be sincere — intentions must be transparent

### Semi-Structured Interviews

**Purpose**: Gather rich qualitative data about user behaviors, motivations, expectations and concerns.

**Duration**: 45-60 mins per interview

**Preparation**:
- Define research questions
- Create interview guide (not a script)
- Recruit appropriate participants
- Arrange recording (with consent)

**Interview Structure**:

1. **Warm-up** (5 mins)
   - Introduce yourself
   - Explain purpose
   - Get consent for recording
   - Ask easy opening question

2. **Context Setting** (10 mins)
   - "Tell me about your role..."
   - "Walk me through a typical day..."
   - "How long have you been doing this?"

3. **Core Exploration** (25-30 mins)
   - Open-ended questions about topic
   - Follow interesting threads
   - Use "tell me more" and "why"
   - Avoid leading questions

4. **Specific Probes** (10 mins)
   - Test specific hypotheses
   - Show stimulus materials if relevant
   - Ask about specific scenarios

5. **Wrap-up** (5 mins)
   - "Is there anything I haven't asked?"
   - "Who else should I talk to?"
   - Thank them

**Key Techniques**:
- Ask "why" five times
- Mirror their language back
- Sit in silence (let them fill it)
- Note non-verbal cues
- Separate observation from interpretation

**Challenges**:
- Participants may say what they think you want to hear
- Lab settings feel unnatural
- Some participants are difficult to interview
- Requires skill and practice

---

### User Testing

**Purpose**: Test designs with users to understand expectations, what works well and what to improve.

**Duration**: 45-60 mins per session

**Preparation**:
- Define what you're testing and why
- Create realistic prototype
- Write task scenarios
- Recruit 5-8 participants
- Set up recording

**Session Structure**:

1. **Introduction** (5 mins)
   - Explain we're testing the design, not them
   - Get consent for recording
   - Encourage thinking aloud

2. **Warm-up Questions** (5 mins)
   - Background questions
   - Current behavior questions

3. **Task Scenarios** (30-40 mins)
   - Present tasks one at a time
   - Observe without helping
   - Note where they struggle
   - Ask clarifying questions after each task

4. **Post-Task Questions** (10 mins)
   - Overall impressions
   - What worked well?
   - What was confusing?
   - How does this compare to alternatives?

**Observation Framework**:

| Task | Success? | Time | Errors | Quotes | Notes |
|------|----------|------|--------|--------|-------|
| 1    |          |      |        |        |       |
| 2    |          |      |        |        |       |

**Facilitator Tips**:
- Don't help — let them struggle
- Use neutral language ("What do you think that does?")
- Note the first click for each task
- Watch for workarounds
- Encourage stakeholders to observe
- Don't make changes until all sessions complete

## Problem Definition Activities

### Problem Statement Writing

**Purpose**: Create a clearly articulated, actionable problem statement that guides the team.

**Duration**: 30-60 mins

**The 4Ws Framework**:

```
┌─────────────────────────────┬─────────────────────────────┐
│           WHO               │           WHAT              │
│                             │                             │
│  Who has this problem?      │  What is the nature of     │
│  Is it validated?           │  the problem?              │
│  Can you prove it?          │  What's the evidence?      │
│                             │  Symptom or root cause?    │
├─────────────────────────────┼─────────────────────────────┤
│       WHERE / WHEN          │           WHY               │
│                             │                             │
│  Where does it arise?       │  Why is it worth solving?  │
│  In what context?           │  How acute is it?          │
│  How often?                 │  What's the business       │
│  Have you observed it?      │  value of solving it?      │
│                             │                             │
└─────────────────────────────┴─────────────────────────────┘
```

**Facilitation Steps**:

1. **Silent Brainstorm** (10 mins)
   - Each person writes stickies for each quadrant
   - One idea per sticky

2. **Share & Discuss** (15 mins)
   - Review all stickies
   - Vote on most important in each quadrant

3. **Write Problem Statement** (10 mins)
   - Each person writes a one-paragraph statement
   - Must include Who, What, Why, Where/When
   - Cannot include a solution

4. **Share & Select** (10 mins)
   - Each person reads their statement
   - Vote on strongest (or combine best elements)

**Problem Statement Template**:

> [WHO — specific user/customer segment] experiences [WHAT — the problem] when [WHERE/WHEN — context and frequency], which results in [WHY — impact and cost of the problem].

**Example**:
> Small business owners (0-4 employees) in trade industries experience significant administrative burden when generating invoices from quotes, which happens 5-10 times per week. This results in delayed payments, cash flow issues, and 3+ hours of admin time that could be spent on billable work.

**Quality Checklist**:
- ☐ Specific about WHO
- ☐ Describes problem, not solution
- ☐ Evidence-based
- ☐ Includes context
- ☐ Quantifies impact where possible
- ☐ "Lack of X" is NOT a problem statement

---

### How Might We (HMW)

**Purpose**: Reframe problems as opportunities for design.

**Duration**: 20-30 mins

**Facilitation Steps**:

1. **Review Problem Statement** (5 mins)
   - Read aloud
   - Ensure shared understanding

2. **Generate HMWs** (10 mins)
   - Each person writes HMW questions on stickies
   - Start each with "How might we..."
   - One question per sticky
   - Aim for 5-10 per person

3. **Share & Cluster** (10 mins)
   - Place on wall
   - Group similar questions
   - Name each cluster

4. **Vote & Select** (5 mins)
   - Dot vote on most compelling
   - Select 1-3 to pursue

**HMW Formula**:

> How might we [ACTION] for [USER] so that [OUTCOME]?

**Good vs Bad HMWs**:

| ❌ Too Broad | ✅ Just Right | ❌ Too Narrow |
|-------------|--------------|---------------|
| HMW improve customer experience? | HMW help first-time users understand pricing? | HMW add a tooltip to the pricing page? |
| HMW make things easier? | HMW reduce the steps to complete checkout? | HMW remove the address field? |

**Tips**:
- Not too broad (impossible to address)
- Not too narrow (implies a solution)
- Should spark multiple possible solutions
- Focus on one aspect of the problem

---

### Root Cause Analysis (5 Whys)

**Purpose**: Move beyond symptoms to understand the true cause of a problem.

**Duration**: 15-30 mins

**Process**:

1. State the problem
2. Ask "Why does this happen?"
3. For each answer, ask "Why?" again
4. Repeat until you reach root cause (usually 5 levels)

**Example**:

```
Problem: Customers are abandoning checkout

Why? → They're getting confused at the payment step
Why? → The form asks for information they don't have ready
Why? → We're requiring fields that aren't necessary for all payment types
Why? → The form was designed for credit cards but we added more options
Why? → We added payment methods without updating the form design
         ↓
Root cause: We lack a process for reviewing UX when adding new features
```

**Fishbone Diagram Alternative**:

```
                    ┌──────────────────────────────────────────┐
    Technology ─────┤                                          │
                    │                                          │
      Process ─────┤              PROBLEM                     │
                    │              STATEMENT                   │
       People ─────┤                                          │
                    │                                          │
       Policy ─────┤                                          │
                    └──────────────────────────────────────────┘
```

Group potential causes by category, then drill into each.

## Ideation Activities

### Brainstorming Workshop

**Purpose**: Generate a broad range of potential solutions collaboratively.

**Duration**: 60-90 mins

**Ground Rules** (display prominently):
1. Defer judgment
2. Encourage wild ideas
3. Build on others' ideas
4. Stay focused on topic
5. One conversation at a time
6. Be visual
7. Go for quantity

**Facilitation Steps**:

1. **Frame the Challenge** (10 mins)
   - Present the HMW question
   - Share relevant research insights
   - Answer clarifying questions

2. **Individual Ideation** (15 mins)
   - Silent brainstorming
   - One idea per sticky
   - Aim for quantity (20+ ideas)

3. **Share & Build** (20 mins)
   - Round-robin sharing
   - Build on each other's ideas
   - Add new ideas as they emerge

4. **Cluster & Theme** (15 mins)
   - Group similar ideas
   - Name each cluster
   - Identify unique/surprising ideas

5. **Vote & Prioritise** (15 mins)
   - Dot voting (3-5 votes each)
   - Discuss top vote-getters
   - Select ideas to pursue

**Output**: 3-5 prioritised ideas for further development

---

### Crazy 8s

**Purpose**: Rapidly generate multiple variations of a solution.

**Duration**: 8 minutes (strict!)

**Materials**: A4 paper, markers, timer

**Setup**:
1. Fold paper into 8 rectangles
2. Set timer for 8 minutes
3. Sketch one idea per rectangle (1 minute each)

**Facilitation Script**:

> "You're going to sketch 8 different ideas in 8 minutes. That's one minute per idea. They can be variations on a theme or completely different approaches. Don't worry about drawing quality — use words, arrows, and simple shapes. Ready? Go!"

**After Crazy 8s**:
- Quick share (30 seconds each)
- No critique at this stage
- Note which ideas have energy

**Tips**:
- Ideas 1-3 are usually obvious
- Ideas 4-6 get more creative
- Ideas 7-8 often the most innovative
- Enforce the time strictly

---

### Solution Sketching

**Purpose**: Develop a single idea in enough detail to test.

**Duration**: 30-45 mins

**Three-Step Process**:

1. **Notes** (10 mins)
   - Review research, HMWs, inspiration
   - Jot down key points to address

2. **Ideas** (10 mins)
   - Rough sketches of possible approaches
   - Don't commit to one yet

3. **Solution Sketch** (20 mins)
   - One detailed sketch
   - Show the key screens/steps
   - Add annotations
   - Make it self-explanatory

**Solution Sketch Requirements**:
- Must stand on its own (no verbal explanation)
- Show the user journey, not just one screen
- Include enough detail to understand the concept
- Title it descriptively

## Prototyping Activities

### Storyboarding

**Purpose**: Plan a prototype by mapping the user journey step-by-step.

**Duration**: 60-90 mins

**Setup**:
- Large whiteboard or paper
- Draw 10-15 empty frames
- Each frame = one moment in the journey

**Facilitation Steps**:

1. **Define Opening Scene** (10 mins)
   - How does user first encounter this?
   - What's the trigger?
   - Set the context

2. **Map Key Moments** (45 mins)
   - Fill in one frame at a time
   - Show what user sees and does
   - Include transitions
   - Annotate with questions/notes

3. **Review & Refine** (15 mins)
   - Walk through the story
   - Fill gaps
   - Cut unnecessary steps

**Storyboard Template**:

```
┌─────────┬─────────┬─────────┬─────────┬─────────┐
│    1    │    2    │    3    │    4    │    5    │
│         │         │         │         │         │
│ Opening │         │         │         │         │
│ Scene   │         │         │         │         │
│         │         │         │         │         │
├─────────┼─────────┼─────────┼─────────┼─────────┤
│    6    │    7    │    8    │    9    │   10    │
│         │         │         │         │         │
│         │         │         │         │ Closing │
│         │         │         │         │ Scene   │
│         │         │         │         │         │
└─────────┴─────────┴─────────┴─────────┴─────────┘
```

### Wireframing

**Purpose**: Create basic visual representations of screens/flows focusing on structure over aesthetics.

**Fidelity Levels**:

| Level | Purpose | Tools | When to Use |
|-------|---------|-------|-------------|
| Sketch | Explore ideas | Paper, whiteboard | Early ideation |
| Lo-Fi | Test structure | Figma, Balsamiq | Validate concepts |
| Mid-Fi | Test interactions | Figma, Proto | Validate flows |
| Hi-Fi | Test look & feel | Figma, Full design | Pre-development |

**Lo-Fi Wireframe Guidelines**:
- Black and white only
- Use placeholder text ("Lorem ipsum")
- Rectangles for images
- Focus on layout and hierarchy
- Include key labels and CTAs

**Facilitator Tips**:
- Introduce wireframes as "intentionally unfinished"
- Teams should make them look unfinished (avoid color)
- Use realistic, accurate content
- Test early and often

## Synthesis & Roadmapping Activities

### Research Synthesis

**Purpose**: Transform raw research data into actionable insights.

**Duration**: 2-4 hours (minimum)

**Rule of Thumb**: Every hour of research requires an hour of synthesis.

**Process**:

1. **Capture** (30 mins)
   - Transfer all notes to stickies
   - One observation per sticky
   - Include quotes where possible

2. **Cluster** (45 mins)
   - Group similar observations
   - Move stickies freely
   - Don't force categories

3. **Name** (30 mins)
   - Title each cluster
   - Write insight statements
   - Note patterns and outliers

4. **Prioritise** (30 mins)
   - Which insights are most important?
   - Which are most actionable?
   - Which need validation?

5. **Document** (30 mins)
   - Create insight cards
   - Link evidence to insights
   - Note implications

**Insight Statement Formula**:

> [USER SEGMENT] [BEHAVIOR/BELIEF] because [MOTIVATION/CAUSE], which means [IMPLICATION FOR DESIGN].

**Example**:
> First-time mobile banking users frequently abandon the registration process at identity verification because they're uncertain why a photo is needed, which means we need to explain the purpose and security measures clearly before requesting sensitive information.

### Roadmapping

**Purpose**: Create a prioritised path to value delivery.

**Duration**: 2-4 hours

**Roadmap Types**:

| Type | Focus | Best For |
|------|-------|----------|
| Feature-based | What we'll build | Engineering planning |
| Value-based | What outcomes we'll achieve | Strategy alignment |
| Now-Next-Later | Relative priority | Uncertain timelines |
| Horizon-based | Strategic phases | Multi-year planning |

**Now-Next-Later Roadmap**:

```
┌──────────────────┬──────────────────┬──────────────────┐
│       NOW        │       NEXT       │      LATER       │
│                  │                  │                  │
│  Committed work  │  High confidence │  Exploratory     │
│  In progress     │  Planned for     │  May change      │
│  Clear scope     │  next period     │  Needs research  │
│                  │                  │                  │
│  • Initiative A  │  • Initiative C  │  • Initiative E  │
│  • Initiative B  │  • Initiative D  │  • Initiative F  │
│                  │                  │                  │
└──────────────────┴──────────────────┴──────────────────┘
```

**Horizon Roadmap**:

| Horizon | Timeframe | Focus | Success Metric |
|---------|-----------|-------|----------------|
| H1: Foundation | 0-3 months | Fix critical issues, build foundations | Stability metrics |
| H2: Differentiation | 3-9 months | Competitive advantages | Market metrics |
| H3: Innovation | 9-18 months | New opportunities | Growth metrics |

### DVF Assessment

**Purpose**: Evaluate solutions against Desirability, Viability and Feasibility.

**Framework**:

```
                         ┌───────────────────┐
                         │                   │
                         │   DESIRABILITY    │
                         │                   │
                         │  Do users want    │
                         │  this?            │
                         │                   │
                         └─────────┬─────────┘
                                   │
                    ┌──────────────┼──────────────┐
                    │              │              │
         ┌──────────▼─────────┐   │   ┌──────────▼─────────┐
         │                    │   │   │                    │
         │     VIABILITY      │───┼───│    FEASIBILITY     │
         │                    │   │   │                    │
         │  Does business     │   │   │  Can we build      │
         │  model work?       │   │   │  this?             │
         │                    │   │   │                    │
         └────────────────────┘   │   └────────────────────┘
                                  │
                           ┌──────▼──────┐
                           │             │
                           │  SWEET SPOT │
                           │             │
                           └─────────────┘
```

**Assessment Questions**:

| Lens | Key Questions |
|------|---------------|
| **Desirability** | Do users need this? Will they use it? Does it solve a real problem? |
| **Viability** | Does it support business goals? Is there a sustainable model? What's the ROI? |
| **Feasibility** | Can we build it with available resources? What are technical risks? Timeline? |

**Scoring Matrix**:

| Initiative | Desirability (1-5) | Viability (1-5) | Feasibility (1-5) | Total | Priority |
|------------|-------------------|-----------------|-------------------|-------|----------|
| A          |                   |                 |                   |       |          |
| B          |                   |                 |                   |       |          |
| C          |                   |                 |                   |       |          |
